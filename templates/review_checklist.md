# 复核清单模板 — 实验结果解释与异常分析

复制本文件到具体项目，逐项勾选。任一项为「否」时，必须在交付前补上对应证据，或在
`unexplained` / `confirmations` 中登记。

## 1. 数据与表结构

- [ ] `case_id` 与输入一致，未改写。
- [ ] 读数来源已记录（内联键路径或文件名），行数为 1 基、表头之后的数据行。
- [ ] 时间列与响应列的识别依据已写明；否则说明用行序作 x 轴。
- [ ] 分组列（批次/通道/孔位/样本）已识别；无分组列时明确声明「原因不能归到对象」。
- [ ] 缺失值、重复行数已统计；单位未声明时已标注，不做自动换算。

## 2. 趋势

- [ ] 每个序列给出方向、首末变化、相对变化、斜率、R²。
- [ ] 平台期（末三点极差 ≤ 末值 2%）单独标记。
- [ ] 趋势结论能回指到具体行号范围。

## 3. 异常与台阶

- [ ] 异常点用序列内稳健 z（median/MAD），阈值与来源已记录。
- [ ] MAD 为 0 时已退回 IQR 规则，并写明所用规则。
- [ ] 异常行给出原值、z、方向、所属批次/通道/重复。
- [ ] 若存在整段台阶，已与单点异常分开报告（`series_level_shift` 或 `series_offset`）。
- [ ] 序列点数不足 6 时，已声明「共享台阶不可分离」。

## 4. 原因与边界

- [ ] 每个原因都有支持证据与排除证据，按证据强度排序。
- [ ] 无证据支持的原因进入 `unexplained`，未强行归因。
- [ ] 饱和/超量程单独标记，并建议稀释复测。
- [ ] 阈值选择与批次/通道归因列入 `confirmations`，等待人工确认。

## 5. 复核与后续

- [ ] 复核步骤是可执行动作，包含字段、行号、批次日志或对照文件。
- [ ] 后续实验写明预期能区分哪两种原因。
- [ ] 对照缺失、重复不足、单位不一致均已进入 `uncertainty`。

## 6. 交付与可复现

- [ ] 单次运行产出 `result.json`、`report.md`、`validation.json`、`provenance.json`。
- [ ] `validation.json` 的 `all_passed` 为 `true`。
- [ ] 同一输入重复运行 `result.json` 字节一致。
- [ ] `output_contract` 全部键存在于顶层；未知键写入 `contract_notes`。
